Macro scripts and the default catalog

Macros are your shortcuts, stored as notes in current configuration / default macros. They register at startup—sync the shared collection to ship new macros without an app release. Same Lisp stack as document managers and Help Show me demos.

What is a macro?

A macro is a named Lisp script stored in your journal’s macro catalog. Macros:

  • Run manually from Menu → Tools / Macros (Run, Edit, Delete)
  • Have no arguments at invoke time (configure via dialogs inside the script)
  • Execute in the UI automation environment when the app is foregrounded
  • Can be triggered from Help, embedded actions, or copied script triggers for logging/automation hooks

The app ships a default macros collection (imported with global configuration). Treat it as a standard library of runnable examples—much built-in behavior is exposed here so you can learn, fork, and customize.

Catalog highlights

Macro Why it matters
show-current-doc-as-markdown Renders the focus note body as Markdown in a dialog—better reading for long prose or exported structure. Body: read focus doc with markdown flag → show-markdown-dialog.
show-flashcard-browser Interactive flashcard self-test (see below).
create-topic-flashcards-walkthrough Checklist-style guide for building a flashcard tree from a lecture, article, or book.

unfinished-chores-reminder Speaks a summary from a chore doc using advanced-doc-chat.

Edit any macro to match your doc ids, scratch defaults, or model preferences.

Flashcard tester (show-flashcard-browser)

Noetic Journal supports learning and self-assessment through a simple tree convention:

  1. Create a flashcard root subject doc (any collection).
  2. Each direct child is a flashcard: title = question, body = answer.
  3. Register decks under the app’s flashcard registry (see Help: “how can I create flashcards from my notes?”).

The macro:

  • Lets you pick a deck and optionally reset per-card stats (last-tested metadata).
  • Chooses the next card among questions ending in ?, preferring cards least recently answered correctly, with prerequisite cards (ancestor questions) satisfied within a forget window.
  • Prompts for your answer; optionally uses local or remote AI to judge similarity to the expected answer (self-test mode, not high-stakes grading).
  • Updates timestamps on success so spacing adapts over time.

Dependency groups and concept-model siblings are described in the Help article Creating flashcards from a linear information presentation.

Help automation uses the same stack

When you ask Help a question and tap Show me, the app runs macro/UI automation toward that goal—then pauses on steps only you can complete (permissions, picking a deck, typing an API key). The Lisp you see in Tools / Macros is the same technology.

Scratch pad vs macros

Macros Scratch << … >>
Environment UI automation (dialogs, focus doc) Journal (background-friendly)
Discovery Named catalog, Help triggers Key/value store, Run button
Best for Guided flows, demos, repeatable UI One-off maintenance, init snippets, scheduled command prototypes

Future shared scratch keys in the app init script will mirror registered journals/to-do lists—same pattern as default macros import.
